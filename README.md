# 더브코 알파 클리닉

출결 · 질문 · 학습 관리 시스템. 학생은 클리닉 출결/질문을 제출하고 이력·성적 분석을
확인하며, **학부모**는 자녀의 기록을 조회합니다. 관리자는 과제 채점과 **테스트 답안
자동 채점**(성적 입력 탭), 학생/응답/학기를 관리합니다.

- **스택**: Next.js 14 (App Router) · TypeScript · Mongoose/MongoDB · iron-session · bcrypt · recharts
- **배포**: Cloudtype 무료 티어 (web 1 + MongoDB 1)

---

## 로컬 실행

```bash
npm ci
cp .env.example .env      # 값 채우기 (MONGODB_URI, SESSION_SECRET)
npm run seed              # 최초 1회 시드 (관리자·과목·클리닉 날짜·데모 데이터)
npm run dev               # http://localhost:3000
```

> 개발 서버를 두 개 띄울 때는 빌드 폴더를 나눠야 서로 깨지지 않습니다.
> `NEXT_DIST_DIR=.next-test npx next dev -p 3111`

기본 계정(시드 후):

| 구분 | 아이디 | 비밀번호 |
|---|---|---|
| 관리자 | `admin` | `admin1234` (`.env` 의 `SEED_ADMIN_PASSWORD`) |
| 학생(데모) | `minjun` / `seoyeon` / `jiho` | `1234` |
| 학부모 | 자녀와 동일 (로그인 화면에서 **학부모** 탭 선택) | 자녀와 동일 (변경 가능) |

> 비밀번호는 **bcrypt 해시로만 저장**되고 평문은 DB·API·화면 어디에도 남지 않습니다.
> 관리자도 볼 수 없으며, 잊었을 때는 **학생 관리 → 수정 → 비밀번호 재설정**으로 새로
> 정해 알려 줍니다(`학부모 비밀번호도 함께 초기화` 선택 가능). 문자 수신번호는 비밀번호와
> 분리된 `Student.phone` 필드입니다.

## Cloudtype 배포

### (1) MongoDB 서비스 먼저 생성
1. 프로젝트 생성 → `+` → 템플릿 **MongoDB** 선택
2. root 계정·비밀번호·디스크 설정 후 배포
3. 배포 후 상세에서 **내부(프라이빗) 호스트·포트(27017)** 확인 → `MONGODB_URI` 조립

### (2) web (Next.js) 서비스 생성
`+` → **GitHub 저장소 배포** → 레포 선택 → 프리셋 **Node.js**

| 항목 | 값 |
|---|---|
| Node 버전 | 20 |
| Install | `npm ci` |
| Build | `npm run build` |
| Start | `npm start` (→ `next start -p 3000`) |
| 포트 | `3000` |

### (3) web 환경변수
```
MONGODB_URI    = mongodb://root:비번@db내부호스트:27017/dubco?authSource=admin
SESSION_SECRET = (랜덤 32자 이상)
NODE_ENV       = production
TZ             = Asia/Seoul
```
> 빌드 OOM 발생 시 `NODE_OPTIONS=--max-old-space-size=512` 추가.

### (4) 첫 배포 후 시드
- 도메인은 첫 배포가 끝나야 발급됩니다.
- Cloudtype web **터미널**에서 최초 1회 실행:
  ```bash
  npm run seed
  ```
  관리자 계정 + 과목/클리닉 날짜 + (데모 데이터)를 upsert 하고 인덱스를 확정합니다.
  MongoDB는 마이그레이션 단계가 없습니다.

> 실서비스에서 데모 학생/세션이 필요 없으면 `scripts/seed.ts` 의 `demoStudents` /
> `seedSessions` / `seedTestMax` 배열을 비우고 배포하세요.

## 데이터 모델 (Mongoose)

- **Student** — 학기와 무관한 로그인 계정(name, username, password)
- **Enrollment** — term+student(unique), 학기별 grade·subjects·status,
  2026 2학기 대상 반의 과목별 1학기 중간·기말·등급
- **Session** — term+student+subject+date(unique), 학생입력(attendance·sources·qNumbers·qTypes·request…),
  관리자입력(hwDone·testScore·solved·adminNote). 유니크: `{student, subject, date}`
- **TestConfig** — subject, date, maxScore(항상 100), detail, `questions[]`(답안 키),
  `answersPublished`, `questionRegions[]`(문항별 PDF 좌표).
  유니크: `{term, subject, date}` (회차별 테스트 설정)
- **Parent** — student(unique), username, password(hash), `selfChanged`
  (학부모가 스스로 비밀번호를 바꿨는지)
- **ShareLink** — token(unique), student, term, subject, date, expiresAt(TTL 인덱스),
  revoked, views. 문자에 붙이는 만료형 성적 링크
- **Bookmark** — student+term+subject+date+label(unique). 오답 노트 별표.
  학생만 표시할 수 있고 학부모는 조회만 합니다
- **Admin** — username(unique), password(hash)
- **GridFS `testfiles`** — 회차별 시험지·답지 파일 (metadata: term/subject/date/kind)
- **Settings** — 싱글턴: subjects[], clinicDates[]
- **Term** — name(unique), subjects[], clinicDates[], clinicDatesBySubject{반→날짜[]},
  closedSubjects[] (먼저 종료한 반), active(학기 진행 여부), order

`Session` 에는 학생 답안(`testAnswers`), 자동 채점 여부(`testAuto`), 100점 환산 여부
(`testScale100`)가 함께 저장됩니다. **테스트 점수는 모두 100점 만점**입니다.

예전에 "맞은 개수"로 저장해 둔 점수는 아래 스크립트로 100점 환산했습니다 (10문항 중 7개
→ 70점, 20문항 중 3개 → 15점). 여러 번 실행해도 안전합니다.

```bash
npx tsx scripts/rescale-scores-100.ts            # DRY RUN
npx tsx scripts/rescale-scores-100.ts --apply    # 반영
```

## 테스트 성적 (성적 입력 → 자동 채점 → 분석)

**관리자 · 성적 입력 탭** (반 + 클리닉 날짜 선택)

1. **그날의 테스트 답안(정답) 입력** — 문항 수 기본 10개, 자유롭게 변경. 문항마다
   정답·배점·유형(출제 단원)·난이도·문제 형태를 넣습니다.
   - 정답은 **문자/문자열**도 됩니다. 복수 정답은 `|` 로 구분합니다 (예: `3|③`).
   - **수식 기호**는 답 입력칸 위의 팔레트(≤ ≥ ≠ ± √ ∞ ⊂ ∈ …)를 누르거나 키보드 약어로
     넣습니다 (`<=`→≤, `>=`→≥, `!=`→≠, `+-`→±, `^2`→², `sqrt`→√, `inf`→∞, `pi`→π).
     채점은 `0≤a≤3/4` 와 `0<=a<=3/4` 를 같은 답으로 봅니다.
   - 답이 길면 그 문항 칸이 자동으로 넓어져 학생 답안 표에서도 잘리지 않습니다.
   - 각 문항의 **+부분문제** 버튼으로 `8-(1)`, `8-(2)` 처럼 나눌 수 있고, 부분문제가
     생기면 그 문항은 부분문제만 채점합니다.
   - **난이도**는 최상/상/중/하/최하, **문제 형태**는 `객관식`(보기 수 지정) 또는
     `단답형` 중에 고릅니다. 객관식이어야 보기 선택 비율이 집계됩니다.
   - **배점은 항상 100점 만점**으로 자동 배분됩니다. 주 문항 수로 100을 나누고,
     부분문제가 있으면 그 문항 몫을 다시 나눕니다 (10문항 중 1번이 둘로 나뉘면
     2~10번 각 10점, 1-(1)·1-(2) 각 5점). 개별 배점을 직접 고칠 수도 있고,
     **100점 균등 배분** 버튼으로 언제든 되돌립니다. 저장하면 그 회차가 재채점됩니다.
2. **시험지·답지 업로드** — PDF/이미지/HWP, 파일당 20MB. 학생·학부모가 다운로드합니다.
   PDF는 업로드 직후 **문항 위치 확인** 화면이 떠서, 문항별 영역을 잡아 둘 수 있습니다
   (아래 참고).
3. **학생별 답안 입력** — 표에 바로 입력하면 자동 저장·자동 채점되고 점수가 즉시 보입니다.
   `Enter` 다음 학생, `← →` 문항 이동, `↑ ↓` 학생 이동, 객관식은 한 자리 입력 시 자동으로
   다음 문항으로 넘어갑니다(끄기 가능). 미응시 학생은 비워 둡니다.

> **클리닉 현황 · 테스트/과제** 탭에서는 더 이상 점수를 입력하지 않습니다. 과제(프린트/부교재)
> O·△·X 만 입력하고, 테스트 점수는 자동 채점 결과를 읽기 전용으로 보여줍니다.
> 답안 키가 없는 **과거 회차의 수동 입력 점수는 그대로 보존**되어 통계·문자에 계속 쓰입니다.

**학생 · 학부모 화면**

| 탭 | 내용 |
|---|---|
| 전체 통계 | 기존 과제 완료율·테스트 평균·점수 추이 |
| 테스트 성적 | 상단 **학기 · 과목 · 회차** 선택기에서 회차를 고르면 그 회차 결과가 바로 위에 나옵니다(기본값 = 가장 최근 회차). 회차 결과는 **점수 분포(91~100 / 71~90 / 51~70 / 31~50 / 0~30)** 와 문항별 **정답률 낮은 순·유형·배점·정답·나의 답안·정오·전체 정답률·답안 분포**. 그 아래에 지금까지의 회차 목록(내 점수·출결·반 평균·최고점·등수·시험지/답지)이 있고, 줄을 누르면 위 결과가 그 회차로 바뀝니다 |
| 문항 분석 | 회차를 골라 **문번·출제 단원·채점표(O/△/X)·배점·난이도·전체 오답률**을 보고, 문항별 **문제 / 답·해설**을 바로 열거나 **별표(★)** 를 찍습니다. 아래에 **유형별 강약점**(내 정답률 vs 전체 정답률)이 이어집니다 |
| 오답 노트 | 과목별로 틀린 문항을 모아 봅니다. **유형 다중 선택**(검색·개수 표시), **별표만** 보기, 15문항씩 **페이지 넘김**, 문항별 **문제 / 답·해설** 잘라 보기. 우측 상단 **오답 노트란?** 버튼에 사용법이 있습니다 |
| 마이페이지 | 계정 정보·비밀번호 변경 |

회차별 **공개/비공개** 토글(성적 입력 탭)로 아직 보여주고 싶지 않은 회차는 숨길 수 있습니다.

**답안 분포**(테스트 성적 상세)는 객관식이면 보기 번호 순으로, 단답형이면 정답을 앞에 두고
많이 쓴 답 순으로 최대 6종까지 보여 주고 나머지는 **기타**로 묶습니다. 빈칸으로 낸 답안은
**미제출**로 표시됩니다. 비교는 정규화된 값으로 하되 화면에는 **학생이 실제로 쓴 표기**를
그대로 보여 주므로, `0 ≤ a ≤ 3/4` 와 `0 <= a <= 3/4` 가 같은 정답으로 묶이면서도 각자의
표기로 보입니다.

**정렬**: 오답 노트와 유형별 강약점 표는 **표 상단을 누르면 그 기준으로 정렬**되고, 한 번 더
누르면 오름/내림이 바뀝니다(회차·문번·단원·난이도·정답률·배점 / 단원·문항 수·내 정답률·전체
정답률·차이).

**별표(★)**: 오답 노트와 문항 분석 어디서나 찍을 수 있고 같은 목록을 공유합니다. 오답 노트의
**별표만** 보기에서는 맞힌 문항도 함께 보여 줍니다(`Bookmark` 컬렉션).

**단원 순서**: 성적 입력 탭의 **단원 순서** 버튼에서 반별 유형(출제 단원)을 배우는 순서대로
한 줄에 하나씩 적어 두면, 학생 화면의 유형별 강약점을 그 순서로 정렬할 수 있습니다
(`Term.typeOrderBySubject`).

### 문항별 "문제 · 답/해설" 잘라 보기

학원 시험지 PDF(jsPDF 출력)는 **텍스트 레이어가 없는 이미지**라 글자를 읽어낼 수 없습니다.
그래서 브라우저에서 페이지를 그린 뒤 **여백(빈 줄)을 분석해 문항 블록을 나누고**, 각 문항이
"몇 쪽의 어느 영역"인지 **좌표만** 저장합니다.

- 문항 시작은 **왼쪽에 짧고 큰 숫자(문항 번호)** 가 오는 줄을 찾아 자동으로 잡습니다.
  해설이 다음 단·다음 장으로 이어지는 부분은 앞 문항에 자동으로 이어 붙습니다.
- 자동 인식이 틀리면 **문항 위치 확인** 화면에서 블록을 눌러 켜고 끄면 번호가 다시 매겨집니다.
  파일 목록의 스캔 아이콘으로 언제든 다시 열 수 있습니다.
- 학생·학부모 **오답 노트**에서 틀린 문항의 `문제` / `답·해설` 버튼을 누르면 그 부분만
  잘라서 보여 줍니다(원본 PDF를 브라우저에서 잘라 그리는 방식).
- **오답 PDF**: 오답 노트에서 **왼쪽 칸을 체크해 고른 문항**(체크가 없으면 화면에 걸린 조건
  전체)으로 인쇄용 PDF를 만듭니다 (`lib/wrong-pdf.ts`, jsPDF).
  - **문제지** — 문제만. 풀 공간이 남도록 한 단(세로 절반)에 최대 두 문항씩 넣고,
    반 칸에 안 들어가는 문항은 한 단을 통째로 씁니다.
  - **해설지** — 답·해설만 빈칸 없이 A4 2단으로 채웁니다.
  - `문제지 + 해설지`를 고르면 파일 2개를 한 번에 받습니다.
  - 표 위 **전체 선택** 버튼으로 쪽을 넘기지 않고 조건에 걸린 문항을 한 번에 고릅니다.
  - 한글 라벨·머리글은 캔버스로 그려 넣어 PDF에 한글 폰트를 넣지 않아도 깨지지 않습니다.
- 문항 위치를 잡아 두지 않은 회차는 같은 자리에 **시험지 · 해설지 전체 열기** 버튼이
  나오므로, 위치를 안 잡아도 문항별로 자료를 바로 열어 볼 수 있습니다.
- 본문 아래 끝은 바닥글 위 가로선을 찾아 자르기 때문에 페이지 아래까지 내용이 이어져도
  마지막 줄이 잘리지 않습니다.
- 저장되는 좌표는 한 회차에 **3~4KB** 수준이라 DB 용량에 거의 영향이 없습니다.

### 성적 공유 링크 (문자에 붙이는 만료형 링크)

**주간 안내 문자** 탭에서 `성적 링크 첨부`를 켜면, 고른 회차마다 학생별 링크를 만들어 문자
본문에 붙입니다. 학부모가 누르면 **로그인 없이** 사이트의 그 회차 성적 상세가 그대로 열립니다
(점수 분포 · 평균 · 등수 · 과제 · 문항별 표 · 답안 분포). 사진과 달리 화질·용량 제한이 없고,
문자 한 통(LMS)이면 됩니다.

- 토큰은 **128비트 난수**(`crypto.randomBytes(16)`)이고, 한 토큰이 여는 범위는
  **그 학생 · 그 반 · 그 날짜 하나**뿐입니다. 다른 회차·다른 학생은 같은 링크로 볼 수 없습니다.
- **유효기간**(기본 30일, 1~180일)이 지나면 MongoDB TTL 인덱스가 문서를 지워 링크가 죽습니다.
  관리자가 즉시 끊고 싶으면 `DELETE /api/admin/share-links?token=…` 로 폐기합니다.
- 같은 회차를 다시 보내면 **살아 있는 링크를 재사용**해 링크가 늘어나지 않습니다.
- 검색엔진 차단(`robots.txt` + `X-Robots-Tag`), `Referrer-Policy: no-referrer`(주소가 외부로
  새 나가지 않게), `Cache-Control: no-store` 를 적용했습니다.
- 로그인 없는 화면이라 **시험지·해설지 내려받기는 감춥니다.** 파일은 로그인해야 받습니다.
- 문항은 **문번 순**으로 보여 줍니다(앱의 테스트 성적 탭도 같습니다. `정답률 낮은 순` 은
  열 값으로 그대로 확인할 수 있습니다). 휴대폰에서는 표 대신 **문항 카드**로 접혀
  가로 스크롤 없이 읽힙니다.
- 우측 상단 **성적 이미지 / 추이 이미지** — 문자에 붙는 것과 같은 카드를 용량 제한 없는
  **PNG** 로 만들어 화면 안 상자에 띄웁니다. 휴대폰은 이미지를 **길게 눌러 사진에 추가**,
  PC 는 상자 아래 **이미지 파일로 저장** 을 누르면 됩니다. (새 창/팝업은 사파리에서
  막히는 경우가 있어 쓰지 않습니다.) 화면 아래쪽에는 **최근 6회 점수 추이** 그림이
  함께 보입니다.
- 열람 횟수와 마지막 열람 시각을 기록합니다(`ShareLink.views`).
- 링크 주소는 `NEXT_PUBLIC_SITE_URL`(있으면) → 없으면 **관리자가 보고 있는 사이트 주소**를
  씁니다. `localhost` 에서 실제 발송하려 하면 휴대폰에서 열리지 않으므로 막습니다 —
  **배포된 주소로 접속해 보내거나** `.env` 에 `NEXT_PUBLIC_SITE_URL` 을 넣어 주세요.
  (테스트 발송은 내 번호로만 가므로 localhost 에서도 흐름을 확인할 수 있습니다.)
- 문자 본문은 **인사말 → 회차별 점수·과제 진행률 → 회차별 링크** 순서로 나갑니다.

> 링크를 아는 사람은 누구나 그 화면을 볼 수 있습니다(문자로 보낸 사진과 같은 성격입니다).
> 민감도가 높다고 판단되면 유효기간을 짧게 두거나 링크를 폐기하세요.

### 주간 문자에 성적 카드 이미지 첨부 (MMS)

**주간 안내 문자** 탭에서 `성적 카드 이미지 첨부`를 켜면 학생마다 카드 이미지를 만들어
**사진 문자(MMS)** 로 보냅니다. 카드는 두 종류입니다.

1. **회차 카드** — 고른 날짜마다 한 장씩 (여러 반을 들으면 반마다).
   학생 화면의 **테스트 성적 상세를 그대로 옮긴 이미지**입니다 — 점수 분포, 내 점수·전체
   평균·최고점·등수, **그날 과제 진행(O/△/X)**, 그리고 문항별 표(정답률 낮은 순·문번·유형·
   배점·정답·나의 답안·정오·전체 정답률). 관리자 전용 `GET /api/admin/round-cards` 가 학생 화면과 같은
   분석 데이터를 내려주고, 그 데이터를 캔버스로 그립니다.
   문자 사진은 휴대폰에서 작게 보이므로 **답안 분포 열은 카드에서 빼고 글씨를 키웠습니다**
   (답안 분포·오답 노트는 사이트에서 봅니다).
2. **점수 추이 카드** — 반마다 한 장. 최근 6회 점수와 반 평균을 꺾은선으로 보여 줍니다.

즉 `9/12·9/13` 두 날짜를 고르고 한 반을 듣는 학생이면 **3장(회차 2 + 추이 1)** 이 갑니다.
발송 전 **미리보기**로 실제로 나갈 장수와 각 장의 용량을 확인할 수 있고, 확인창에 총 건수와
예상 비용이 표시됩니다.

- 이미지는 **관리자 브라우저에서 캔버스로 생성**합니다. 서버에 이미지 라이브러리·한글 폰트를
  둘 필요가 없어 무료 티어에서도 가볍게 돌아갑니다 (`lib/score-card.ts`).
- 카드 머리말에는 **이름 · 학교 · 학년**이 들어갑니다 (`Student.school`, 학생 관리에서 입력).
- **1500px 폭 · 세로 1440 이하** JPEG(솔라피 한도를 꽉 채운 최대 해상도)로 그리고,
  **200KB 이하**가 되는 **가장 높은 품질**(0.96부터 한 단계씩)로 인코딩합니다. 문항이 많으면
  표 행 높이를 줄여 세로 한도 안에 맞춥니다. 한도를 넘는 이미지는 업로드 단계에서
  `TooHighResolution` 으로 거절됩니다.
- 서버는 같은 이미지를 **한 번만 업로드**해 재사용하고(`POST /storage/v1/files` → `fileId`),
  발송 시 `type: "MMS"` 와 `imageId` 를 함께 보냅니다.
- 이미지를 붙이면 요청 용량이 커지므로 **한 번에 5명씩** 나눠 보냅니다.
- **단가**: SMS 13원 / LMS 29원 / **MMS 60원** (VAT 별도). 이미지를 켜면 건당 약 60원입니다.
- **인사말은 첫 통에만** 들어갑니다:
  `안녕하세요 더브코 알파 오현민T 조교입니다. / 이번 주 OO 퀴즈 점수 및 과제 진행 여부 알려드립니다 :)`
  (관리자가 적은 **추가 안내 문구**도 이 첫 통에 함께 붙고, 그 아래 첫 사진 설명이 한 줄 붙습니다.)
  나머지 사진에는 `9/13 대수 테스트 성적표`, `대수 점수 추이` 같은 **한 줄 설명**만 붙습니다.
  MMS 는 **한 통에 사진 1장**만 넣을 수 있고 **본문을 비울 수 없어**(솔라피 `1010 text 필드는
  필수 입력요소 입니다.`) 사진 3장이면 문자도 3통이지만, 긴 인사말은 한 번만 갑니다.
- 솔라피는 **한 요청에 같은 번호가 두 번 들어가면 "중복 수신번호"로 막습니다.** 그래서
  한 묶음 안에서 번호가 겹치지 않도록 나눠 보냅니다 — 학생 한 명에게 카드 여러 장을 보낼
  때나 **형제자매가 같은 학부모 번호를 쓰는 경우**에도 전부 정상 발송됩니다.
- `SMS_TEST_TO` 안전장치와 테스트 발송(내 번호로 전부 보내기)은 그대로 동작합니다.

> **RCS 슬라이드(캐러셀)는 아직 쓰지 않습니다.** 한 통에 카드 여러 장을 넘겨 볼 수 있어
> 이 용도에 딱 맞지만, RCS Biz Center **브랜드·대화방 등록**(사업자등록증, 통신서비스
> 가입증명원, 각 2영업일 심사)과 발신번호 재등록이 선행되어야 하고, 수신 단말도
> **갤럭시 S8 이후 · iOS 26 이상**으로 제한되어 미지원 단말은 결국 MMS 대체발송으로
> 나갑니다. 현재 계정에는 RCS 브랜드가 없어 발송은 물론 검증도 되지 않습니다
> (`RCS_MMS` 등록 시 `1010 rcsOptions값은 필수 입력요소 입니다`). 학원 사업자등록증으로
> 브랜드 등록을 마치면 그때 다시 검토합니다.

### 파일 저장소 · 용량
시험지·답지는 **MongoDB GridFS(`testfiles` 버킷)** 에 저장합니다. 별도 스토리지 서비스나
환경변수가 필요 없고 재배포해도 파일이 남습니다. 파일당 20MB 제한입니다.

> **용량 주의**: 실제 용량을 차지하는 것은 PDF 원본입니다(예: 시험지 1.3MB + 해설지 2.4MB).
> 회차마다 두 파일을 올리면 한 반 한 학기(약 15회)에 **50MB** 안팎이 쌓입니다. 무료 DB
> 용량(예: Atlas M0 512MB)을 고려해 필요 없는 회차 자료는 지우거나, PDF를 조금 낮은
> 해상도로 내보내 올리는 것을 권장합니다. 3MB가 넘는 파일은 업로드 시 안내가 뜹니다.

## 보안

- **비밀번호**: bcrypt(10 라운드) 해시만 저장. 평문은 DB·API 응답·화면 어디에도 없습니다.
  최소 6자. 본인 변경은 **현재 비밀번호 확인** 후에만 되고, 관리자는 값을 보지 못한 채
  **재설정**만 할 수 있습니다(`scripts/hide-passwords.ts` 로 기존 평문을 제거했습니다).
- **로그인 보호**: 아이디·비밀번호는 문자열로만 다뤄 **NoSQL 주입**을 막고(객체를 넣으면 400),
  같은 아이디+IP 로 10분에 10번 실패하면 **10분 잠금**(429)입니다.
- **세션**: iron-session 암호화 쿠키 — `httpOnly`, 운영에서 `secure`, `sameSite=lax`.
  세션에는 계정 id·역할만 담깁니다.
- **권한**: 모든 `/api/admin/*` 는 `requireAdmin`, 학생·학부모 화면은 `requireViewer`,
  쓰기는 `requireStudent`. 세션 레코드 수정은 **본인 소유인지 다시 확인**하고, 시험지·답지는
  **그 반에 등록된 학생/학부모**에게만, 공개 설정(`answersPublished`)이 켜진 회차만 내려갑니다.
- **응답 헤더**: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`(공유 링크는 `no-referrer`), `Permissions-Policy`, 운영에서 HSTS.
- **업로드**: PDF·이미지·HWP 만, 파일당 20MB 제한. 내려줄 때 파일명을 인코딩합니다.
- **개인정보**: `.env`, 명단 엑셀(`*.xlsx/csv`), 시험지 PDF 는 저장소에 올리지 않습니다.

## 학부모 계정

학생 계정 1개당 학부모 계정 1개가 대응합니다(`Parent`). **아이디·비밀번호는 학생과 동일**하게
시작하고, 로그인 화면의 **학부모** 탭으로 들어가면 조회 전용 화면이 열립니다.

- 학부모 계정 문서가 아직 없으면 **첫 로그인 때 자동 생성**됩니다.
- 학생·학부모 모두 **마이페이지에서 비밀번호를 변경**할 수 있습니다.
- 학부모가 스스로 바꾸기 전까지는 학생 비밀번호가 바뀔 때 학부모 비밀번호도 함께 맞춰집니다.
  (한 번이라도 직접 바꾸면 그때부터 독립됩니다 — 관리자 **학생 관리** 탭 `학부모 계정` 칸에
  `따로 변경됨` 으로 표시. 비밀번호 값 자체는 보이지 않습니다.)
- 학부모는 클리닉 입력·1학기 성적 입력을 할 수 없습니다(서버에서도 403).

기존 학생 전원에게 학부모 계정을 미리 만들어 두려면:
```bash
npx tsx scripts/create-parents.ts           # DRY RUN
npx tsx scripts/create-parents.ts --apply   # 실제 생성
```

## 학기(분기) 운영

데이터는 **학기(Term)** 단위로 분리됩니다. 각 학기가 자기 **반·클리닉 날짜·명단·기록**을 가지며,
학생 계정은 학기와 무관하게 유지되고 학기별 **등록(Enrollment)** 으로 수강 반이 관리됩니다.
학생은 학기 선택으로 **지난 학기 기록**을 조회할 수 있습니다. 여러 학기를 동시에
진행 상태로 둘 수 있어 여름학기와 2학기를 병행해도 등록·클리닉·성적 데이터가 섞이지 않습니다.

**관리자 화면**: 상단 학기 선택기로 전환, **학기 관리** 탭에서 학기 생성/진행 시작·종료/설정(반·날짜)/삭제.
새 학기 만들 때 이전 학기에서 반·날짜·명단을 복사할 수 있습니다.

**반(수업)별 진행/종료**: 학기 설정에서 반마다 따로 **진행 종료 / 진행 시작**을 누를 수 있어,
학기 전체를 닫지 않고 먼저 끝난 반만 정리할 수 있습니다(`Term.closedSubjects`).
같은 화면에서 **반별 클리닉 날짜를 추가·삭제**합니다(`Term.clinicDatesBySubject`, 공통
`clinicDates` 는 그 union 으로 자동 갱신). 종료된 반은 **클리닉 현황·테스트/과제**의 과목
목록과 **학생 입력 화면**에서 사라지고, 학생의 신규 제출도 서버에서 막힙니다(403).
쌓인 기록은 지워지지 않으며, 관리자는 두 화면의 `종료 수업 포함` 체크로 다시 꺼내볼 수
있습니다. 반 이름은 학생 등록·기록과 문자열로 연결되어 있어 설정 화면에서 바꿀 수 없고
추가·삭제만 가능합니다.

`2026 2학기`의 `고1 공수2`, `고2 미적분1`, `고2 확통` 수강생에게는 학생 화면에
**1학기 성적 입력** 탭이 표시됩니다. 학생은 실제 1학기 학교 과목명과
중간·기말고사 성적, 등급을 입력합니다. 학교 과목은 여러 개 추가·삭제할 수 있으며 학생의
2학기 등록(Enrollment)에 목록으로 저장됩니다. 관리자는 별도 **학교 성적 관리** 탭에서
현재 수강반을 선택하고 학생별 여러 학교 과목을 각각 조회합니다.

**2026 2학기 첨부 명단 정확 반영** (기본은 DRY RUN):
```bash
npx tsx scripts/setup-2026-second-term.ts
npx tsx scripts/setup-2026-second-term.ts --apply
```
기존 학생 계정은 재사용하고 신규 계정만 생성합니다. 이 스크립트는 2학기 명단만 조정하며
여름학기와 기존 학생 기록은 수정하지 않습니다. 엑셀 파서는 검토한 첨부 파일의 SHA-256이
일치할 때만 실행됩니다.

**새 학기 명단 일괄 등록 (엑셀)**:
```bash
# 진행 학기가 여러 개면 반드시 대상 학기 지정
npx tsx scripts/import-students.ts --term="2026 가을"
```
기존 계정은 재사용(비번 유지)하고 신규만 생성하며, 그 학기 반 목록도 자동 갱신됩니다.

**클리닉 날짜 추가** (학기 대상):
```bash
npx tsx scripts/set-clinic-dates.ts --term="2026 가을" 2026-09-05 2026-09-06
```

`2026 여름특강`과 `2026 2학기`의 **과목별 요일 일정 반영** (기본은 DRY RUN):
```bash
node --import tsx scripts/setup-subject-clinic-dates.ts
node --import tsx scripts/setup-subject-clinic-dates.ts --apply
```
과거 Session/TestConfig가 있는 날짜는 과목별 일정에 합쳐 보존하고, 두 학기의 일정 필드만
트랜잭션으로 갱신합니다. Enrollment·Session·TestConfig 문서는 수정하거나 삭제하지 않습니다.

**최초 도입 마이그레이션** (기존 전역 데이터 → 첫 학기):
```bash
npx tsx scripts/migrate-terms.ts "2026 여름특강"   # 최초 1회, 멱등
```

## 디버깅용 예시 반 (대수)

화면을 확인하려고 만든 **예시 데이터**입니다. 실제 반과 섞이지 않게 아이디를 `demo01~demo15`
로 쓰고, 한 번에 지울 수 있습니다.

```bash
npx tsx scripts/demo-subject.ts                    # DRY RUN
npx tsx scripts/demo-subject.ts --apply            # 2026 2학기에 "대수" 반 생성
npx tsx scripts/demo-subject.ts --remove --apply   # 예시 데이터 전부 삭제
```

- 학생 20명 — `demo01`~`demo15`(비밀번호 `1234`)와, 실제 번호로 문자까지 시험해 볼
  `demo16`~`demo20`(비밀번호 = 그 번호). 클리닉 10회차(8/15 ~ 9/13)
- 학교·학년이 모두 채워져 있어 테스트 성적 화면 머리말(`이름 · 학교 · 학년`)을 확인할 수 있습니다
- 회차마다 10문항 답안 키(8번은 부분문제 2개) · **유형 20종** · 난이도 5단계
- 학생별 실력을 다르게 줘서 점수·오답률·분포가 실제처럼 보입니다
- 시험지·답지는 이미 올라간 `공수2_8월1일` PDF를 **참조**로 재사용합니다
  (`metadata.aliasOf` — 파일을 복사하지 않아 용량이 늘지 않습니다)

같은 시험지를 여러 회차가 함께 쓸 때, 한 회차에서 잡은 문항 위치를 나머지 회차로 복사합니다.

```bash
npx tsx scripts/copy-regions.ts --subject="대수" --from=2026-08-15 --apply
```
